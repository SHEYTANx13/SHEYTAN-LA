The run 45323044820 platform build (commit `d6778fd`, the squashed landing of the previous candidate) failed four jobs. All three failure mechanisms are now fixed at root-cause level, and the owner-directed iOS retirement removes the remaining warning lane:

- **CGO errno persistence — the darwin attribution root cause (macos-arm64, macos-x64, iOS lane host)**: cgo's two-result form surfaces the POSIX thread's errno AT CALL RETURN as the Go error, and a successful libproc call never resets errno; one failed candidate probe (EPERM on a root-owned process — the pid list starts at launchd on every macOS runner — or ESRCH on a candidate that exited mid-walk) LEFT errno set and every LATER successful helper call inherited the stale errno as a Go error. The whole walk collapsed to ErrPortOwnerUnknown and the entire attribution family (`TestListeningProcessFindsSelfOwnedListener`, `TestOwnProcessListenerAttributed`, `TestIPv6ListenerAttributed`, `TestListeningProcessAttributesForeignChildListener`, `TestListeningProcessDeadOwnerRefused`, `TestListeningProcessIPv6LoopbackAttributed`) plus `internal/llm TestAdoptionAcceptsManagedEngine` (engine adoption refuses an unattributable port owner) failed deterministically on every darwin host — while Linux (pure-Go /proc walk, no cgo errno) stayed green. Every libproc helper in `identity_darwin.go` now resets errno to 0 BEFORE its call (c_start_time already carried the pattern): successes answer err == nil, real failures keep their exact typed kernel errno. New darwin cgo regression test `TestListeningProcessAfterFailedProbeSucceeds` reproduces the poison deterministically (LockOSThread + failed probe + immediate attribution must succeed).
- **`TestListeningProcessDeadOwnerRefused` recycled-pid honesty extended**: an observed-dead pid recycled into an UNINSPECTABLE process (inspection denied — e.g. a root-owned incarnation on a busy runner) now records the honest environment skip exactly like the already-handled successful-probe case; the answer describes the NEW process, never the observed-dead one. Any other typed class still fails loudly; a still-dead pid must still answer typed ErrProcessNotFound.
- **Android repo-cleanliness guard — root cause reproduced locally (android-arm64)**: `scripts/ci/module-preflight.sh` runs `go mod download all` on every lane; the committed `go.sum` was incomplete relative to the module graph (missing the `h1:`/`go.mod` sums `go mod download all` requires), so the preflight MODIFIED the tracked `go.sum` (+368 lines, additions-only, reproduced on go1.27.4 in this sandbox) and the packaging-lane cleanliness guard (`git status --porcelain`) failed deterministically — only the android lane runs the guard after packaging, which is why it alone went red. The completed `go.sum` is committed (generated by the exact command CI runs at the pinned Go version); `go mod download all` is now a verified tree no-op and the guard stays strict.
- **iOS lanes retired (owner direction)**: the `ios-simulator-arm64` and `ios-device-arm64` matrix targets, their lane scripts (`scripts/build/ios.sh`, `scripts/build/ios-device.sh`), the signing prerequisite document and every workflow/doc reference are removed; the platform matrix is FIVE targets (windows-x64, linux-x64, macos-arm64, macos-x64, android-arm64). The releasecontract suite now FAILS on any `ios-*` matrix target or retired iOS artifact name (retirement is pinned, not just deleted). This removes the iOS-device warning (missing Apple signing secrets) and the iOS-lane-host test surface from every future run. The retirement is recorded in `docs/retired.md`.
